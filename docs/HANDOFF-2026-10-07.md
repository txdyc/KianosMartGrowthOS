## 3. 已确认的关键决定

**架构层面**（v1.1 评审得出，v1.2 沿用）
- WooCommerce 是唯一交易主系统。Kiano 不自建订单，**不接管 Paystack webhook**（每个模式只能配一个 URL，已被 Woo 插件占用）。
- 利润口径为 CM1/CM2/CM3 + POAS；Max CAC 只计算，不存储。
- 归因包含 Click-to-WhatsApp（WhatsApp webhook 的 `referral` 字段）。
- 技术栈：Spring Boot 3 + Java 21（模块化单体）、MyBatis-Plus、Next.js + TypeScript、PostgreSQL 16（同时用作任务队列，`SKIP LOCKED`）、MinIO。**不引入 RabbitMQ、ClickHouse，不做多 Agent 编排。**

**开发顺序调整**（本次会话确认）
- 现状：每个 SKU 只有一张宣传图和实物。**第一个开发阶段是物料生成模块（content），Sprint C1–C6。** 利润、广告分析、WhatsApp 等模块（S2–S6）整体顺延，期间用 Google Sheet 和平台后台过渡（用户已接受这个代价）。
- 选定**方案 B**：物料生成是 Kiano 的第一个模块，C1–C6 在笔记本本地运行。C6 之后 Kiano 核心迁移到 VPS，笔记本只保留 kiano-worker。
- 用户**可以实拍照片和短视频**，流水线以"实拍 + AI 增强"为主。
- 图像处理**全部在本地 4090 上运行**（ComfyUI，Windows 原生安装，不进 Docker）；视频片段用 **MiniMax H3 API**。
- 第一版产出四类物料：商品图组、商品文案、广告静态图、短视频。
- **分层覆盖**：全部 SKU 做图组和文案；10–15 个 HERO SKU 另加 12 张广告图和 3 条短视频。

**物料设计原则**（详见规格 §3）
1. AI 只改环境，不改产品；产品像素来自实拍抠图。
2. 价格、COD、参数等文字一律用 HTML/CSS 模板渲染，不让 AI 画字；价格从 Woo 实时读取。
3. 事实表锁定后才生成文案、信息图、参数图。
4. 视频中 AI 生成的时长占比不超过 30%。
5. 每个物料都可追溯来源和版本，可复现。

## 4. 环境信息（本机实测）

- GPU：**NVIDIA RTX 4090 Laptop，16 GB 显存**（不是 24 GB 的桌面版）→ 图像模型需用 fp8 / GGUF 量化版本，GPU 任务单并发。
- Docker 29.8 可用。
- **系统没有安装 Python**（`python` 命令指向 Microsoft Store 占位程序）。ComfyUI 便携版自带 Python，不受影响。
- 操作系统：Windows 11；Git Bash 可用。
- 本目录**还不是 Git 仓库**，文档都未提交。

## 5. 与 KianosMart 仓库的关系

- KianosMart 本地开发环境：在该仓库复制 `.env.example` 为 `.env`，设置 `HTTP_PORT=8080`，然后 `docker compose up -d --build`，访问 `http://localhost:8080`。**Woo 集成测试和发布、回滚的验证都在这里进行。**
- KianosMart 的规则：先在 staging 测试，再上生产；生产部署只通过 `scripts/deploy.sh`。
- C4 的 **kiano-connector** 插件放在 **KianosMart 仓库**的 `wp-content/plugins/kiano-connector/`，需要在 `docker-compose.yml` 的 `wordpress` 服务中添加 bind mount；如果有静态资源，`nginx` 服务也要以只读方式挂载。
- 发布物料需要在 WordPress 中为专用的 Shop Manager 用户创建 Application Password（`wp/v2/media` 不接受 Woo consumer key）。
